# 界面风格和交互设计调研

日期：2026-07-27

本文记录围绕页相随 PageAlong 界面风格优化的调研和结论，主题包括阅读、播客式收听、课程管理、阅读友好和尽可能极简的专业呈现。本文是后续设计规格和实施计划的输入材料，不代表已经批准进入实现的完整范围。

## 产品定位

PageAlong 是一个面向移动学习场景的网页阅读器，用于把粘贴文本和导入文章转成可管理的有声课程记录。

期望用户看到产品后的第一印象：

- 专业、安静、可信。
- 阅读优先，而不是后台管理优先。
- 极简，但不能显得空、粗糙或半成品。
- 适合移动端反复使用。
- 能清楚表达三种核心状态：
  - 阅读文本，
  - 像播客或有声书一样收听，
  - 管理个人课程库。

重要产品边界：

- 真实 TTS、认证、支付、生产级 URL 图片处理等能力尚未完整实现。界面文案和视觉状态不应暗示这些功能已经可用。

## 当前界面状态

当前 Web 前端已经具备一些可用基础：

- `apps/web/src/components/ConsoleShell.tsx` 中有侧边导航和全局搜索。
- 工作台和课程库流程可以直接打开课程并进入阅读工作区。
- 阅读工作区包含左侧文章列表、课程元信息、正文展示、句子高亮和底部音频控制。
- Markdown 阅读器可以把文本单元映射到句子，并支持高亮和点击选中当前句。
- 底部固定播放器区域目前使用浏览器原生 `<audio controls>`。

观察到的主要设计问题：

- 当前产品更像轻量管理后台，而不是阅读产品。
- 课程卡片展示了较多元信息，且视觉权重接近，用户需要逐行解析，不够容易扫读。
- 正文被包在明显的白色卡片中，文章更像后台面板里的内容，而不是产品的主阅读表面。
- 来源信息、标题、状态、正文和播放器的视觉权重接近，阅读流需要更明确的层级。
- 底部播放器功能上可用，但依赖浏览器原生控件，视觉上比较通用。
- 当前句高亮使用较强的琥珀色背景。它能工作，但更像批注或调试态，不够像成熟精致的跟读引导。

## PageAlong 设计原则

### 1. 阅读优先

课程打开后，文章正文应该是产品的主表面。导航、来源信息、状态徽标和管理操作只有在用户需要时才应凸显。

落地含义：

- 使用居中的阅读栏，并保持舒适行宽。
- 避免让正文看起来像通用卡片。
- 来源信息作为文章上方的轻量上下文，而不是单独面板。
- 控件要足够容易发现，但视觉上保持次要。

### 2. 收听是一等模式

当前已经有播放器，但还没有形成成熟收听产品的感觉。音频可用时，PageAlong 应该更接近播客或有声书应用。

播放器应具备的气质和能力：

- 自定义播放/暂停按钮。
- 后退/前进 10 秒或 15 秒。
- 带当前时间和总时长的进度条。
- 倍速控制。
- 当前句子或章节提示。
- 移动端紧凑固定底栏。
- 后续可展开为句子或章节导航。

### 3. 极简是高信号，不是低功能

界面应该去掉装饰噪音和重复元信息，但在合适时机保留必要控制。

落地含义：

- 减少卡片容器数量。
- 优先用留白和字体层级分组，而不是先加边框。
- 徽标只用于可操作或关键状态信息。
- 删除等低频操作尽量进入次级菜单或弱化控件。
- 不要让所有元信息都一样显眼。

### 4. 课程管理要容易扫读

课程库是个人学习队列，不是客户关系管理表格，也不是营销卡片网格。它应该帮助用户快速回答：

- 我应该继续学什么？
- 哪些内容已经可以听？
- 哪些内容还要确认或生成？
- 我最近导入了什么？

落地含义：

- 顶部增加强“继续学习”锚点。
- 将课程库从大卡片堆转向更紧凑的列表行。
- 每行展示标题、进度、状态、更新时间、来源/标签摘要和一个主操作。
- 删除等破坏性操作、低频操作放到菜单或弱化控件里。

### 5. 移动端是主要使用姿态

产品服务移动学习场景，所以桌面布局不应成为移动端的心智模型。

落地含义：

- 移动端正文和播放控制应占主导。
- 文章列表或侧栏应折叠为抽屉，或退回到列表路由。
- 底部播放器需要适配安全区域，并支持单手使用。
- 导入和确认流程在小屏上避免密集并排布局。

## 推荐风格方向

最适合当前产品的方向是：

```text
安静阅读器 + 随行播放器
```

这个方向能让 PageAlong 更像专业阅读/收听工作区，而不是通用后台。

### 视觉语言

建议色彩：

- 纸张背景：`#F7F4ED` 或接近的暖白色，用作页面背景。
- 表面色：`#FFFDF8`，只用于少量需要抬起的区域。
- 墨色：`#171717`，用于主文字。
- 弱化文字：`#6B6760`，用于元信息。
- 细线：`#E5DED2`，用于轻边框。
- 品牌辅助色：低饱和绿色或深青色，例如 `#2F6F5E`。
- 收听强调色：克制的琥珀或金色，例如 `#C98A2E`，只少量用于当前播放状态。

应避免：

- 缺乏对比的一整套米白/奶油色。
- 大面积紫色、蓝紫色渐变。
- 装饰性光球、浮动圆点、通用 AI 风背景。
- 过多嵌套卡片。

### 字体和排版

方向：

- 正文阅读排版要像文章，安静、舒展。
- UI 字体要紧凑、工具化，便于扫读。
- 品牌可以有一点更有性格的显示处理，但要克制。

具体选择：

- 中文正文：可以考虑系统中文宋体或高质量无衬线备用字体，具体要在不同系统上测试，因为中英文混排效果会有差异。
- 界面文字：系统无衬线字体可以接受，前提是间距、层级、字重足够精确。
- 中文长文阅读行高建议在 `1.75-1.9` 左右。
- 桌面阅读栏宽度建议约 `64-72ch`，移动端则使用全宽加舒适内边距。

### 标志性交互

建议把“随行时间轨”作为产品记忆点：

- 音频播放时，当前句子柔和高亮。
- 高亮应该像收听引导，而不是文本批注。
- 可以用一条细进度轨或轻量标记连接播放进度和文章位置。
- 点击句子可以跳转到对应音频位置。

这个交互比装饰性品牌图形更贴合 “PageAlong / 页相随” 这个名字。

## 考虑过的其他方向

### A. 生产力控制台

保留当前侧栏、工作台、卡片语言，只做精修。

优点：

- 实现最快。
- 适合管理动作很多的工作流。
- 可以最大程度复用当前结构。

缺点：

- 阅读产品的第一印象较弱。
- 容易像通用软件服务后台。
- 无法让收听模式显得足够重要。

结论：可以作为渐进清理方案，但不是最好的品牌方向。

### B. 安静阅读器 + 随行播放器

以长文阅读和持续收听作为产品中心。

优点：

- 最贴合产品承诺。
- 能形成专业的阅读/收听感。
- 可以分阶段实施。
- 同时适合移动端和桌面端。

缺点：

- 需要用自定义播放器替换原生 audio 控件。
- 对排版、间距和视觉层级要求更高。

结论：推荐采用。

### C. 播客资料库优先

让产品主要像私人播客应用。

优点：

- 收听心智很强。
- 真实生成音频稳定后很有价值。

缺点：

- 会弱化阅读和正文确认流程。
- 在 URL 确认、真实 TTS、课程组织仍在演进时略早。

结论：适合作为未来演进方向，不适合作为第一次改版目标。

## 页面级建议

### 工作台

当前职责：

- 进入继续学习和导入新内容。

建议调整：

- 让“继续学习”成为最主要的页面区域。
- 减少指标卡，除非它们能直接支持行动。
- 使用紧凑最近列表，而不是重复的大卡片。
- 保留主要导入操作，但不要做成营销式首屏区域。

### 课程库

当前职责：

- 管理碎片化课程。

建议调整：

- 可以考虑调整“碎片化课程”的前台命名。“文章课程”、“资料库”或“阅读库”可能更自然，不那么内部。
- 使用分段筛选：
  - 全部，
  - 可播放，
  - 待确认，
  - 生成中，
  - 星标。
- 使用行式课程条目，突出进度和状态。
- 删除和次要操作不要抢主操作的视觉权重。

### 阅读工作区

当前职责：

- 阅读当前课程、选择句子、收听音频、在课程之间切换。

建议调整：

- 让阅读栏成为视觉中心。
- 移动端折叠课程列表。
- 减少正文的卡片感。
- 来源元信息保持轻量内联。
- 优化当前句高亮，让它更像收听引导。
- 后续可以考虑“专注阅读”模式。

### 播放器

当前职责：

- 底部固定原生音频控件。

建议调整：

- 用自定义紧凑播放器替换原生音频界面。
- 包含播放/暂停、后退、前进、倍速、进度、当前时间和课程标题。
- 保留原生 `<audio>` 元素作为底层播放能力。
- 沿用当前已实现的播放进度保存逻辑。
- 后续支持展开播放器，用于句子或章节导航。

### 导入和确认

当前职责：

- 粘贴文本或提交 URL，查看清洗后的正文，再确认生成音频。

建议调整：

- 导入页保持安静、任务导向。
- URL 确认页要像阅读一篇清洗后的文章，而不是查看一条数据库记录。
- 可见文案不要过度承诺尚未实现的上传、OCR、认证、支付等能力。

## 值得保留和强化的交互细节

- 点击句子跳转音频是很强的产品行为，应该保留。
- 自动滚动到当前句很有用，但应保持平静。用户手动阅读时不要频繁强制跳动。
- 播放进度应该在课程库中可见，不应只显示原始秒数。
- “上次播放：128s” 应改为更适合人的表达，例如 `02:08`、`34%` 或 `继续到第 12 句`。
- 状态徽标应表达下一步动作：
  - 待确认：需要用户确认，
  - 可播放：可以继续听，
  - 生成中：等待完成，
  - 失败：可以重试。
- 删除等破坏性操作应弱化，并尽量二次确认。

## 建议实施优先级

1. 阅读工作区视觉重构：
   - 阅读栏居中，
   - 元信息降噪，
   - 减少卡片边界，
   - 优化句子高亮。

2. 自定义底部播放器：
   - 在现有音频元素外构建自定义控件，
   - 格式化播放进度，
   - 增加倍速和快退/快进。

3. 课程库清理：
   - 强化继续学习区域，
   - 改成更紧凑的列表行，
   - 改善进度显示，
   - 增加分段筛选。

4. 移动端打磨：
   - 折叠课程列表，
   - 处理底部播放器安全区域，
   - 阅读时降低导航权重。

5. 后续可选优化：
   - 阅读偏好设置，
   - 深色/护眼主题，
   - 展开播放器，
   - 课程章节，
   - URL 图片导入实现后支持图文阅读。

## 第一轮改版非目标

- 不做营销落地页。
- 不加装饰性首屏展示区。
- 除非后端能力已经完成，否则不要暗示真实 TTS 已完整接入。
- 不在认证、支付和账号系统尚未实现时重设计这些区域。
- 不为了视觉优化引入大型组件库。
- 没有单独理由时，不偏离现有 Next.js、Tailwind 和 npm 前端栈。
