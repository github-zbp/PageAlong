# PageAlong Interface Style Refresh Design

日期：2026-07-29

## 背景

PageAlong 当前 Web 前端已经具备课程导入、课程库、阅读工作区、句子高亮和音频播放的基础能力，但界面气质更接近轻量后台。第一轮界面优化的目标是把主流程统一成“收听优先的安静阅读器”，让用户打开产品后更容易理解三件事：

- 继续学习或继续收听。
- 管理自己的课程库。
- 阅读正文，并像听播客或有声书一样跟随当前句。

本设计基于 `docs/interface-style-and-interaction-research.md`，并结合本轮确认过的用户偏好。

## 已确认决策

- 改版范围覆盖工作台、课程库、导入页、URL 确认页、阅读页和底部播放器。
- 视觉底色采用“安静阅读器”：暖白纸感背景、深绿主控制、克制琥珀播放/高亮提示。
- 阅读页主姿态偏收听，正文作为同步跟随材料。
- 桌面阅读页左侧优先展示其他文章/课程文章队列，不把当前文章目录作为第一层主导航。
- 桌面阅读页播放器限定在右侧主体区域内，不遮挡左侧文章队列。
- 左侧文章队列支持收缩折叠；折叠后保留展开入口和当前队列提示。
- 移动端采用顶部轻导航 + 页面内抽屉；课程文章列表在抽屉中打开。
- 移动端播放器采用底部随行播放器。
- 前台导航和页面标题使用 `课程库`，不再把“碎片化课程”作为主要用户可见名称。

## 非目标

- 不实现真实 TTS、认证、支付、文件上传、OCR 或生产级可观测性。
- 不暗示音频已即时生成完成；保留现有 fake TTS / 音频生成骨架的真实能力边界。
- 不引入大型组件库。
- 不重构后端数据模型；`library_type` 等内部字段保持现状。
- 不在第一轮实现展开播放器、文章目录系统或复杂播放队列。
- 不做营销落地页。

## 视觉系统

### 色彩

- 页面背景：`#F7F2E8`，作为整体暖白纸感底色。
- 阅读表面：`#FFFDF8`，用于正文、表单和关键内容面。
- 辅助表面：`#F3EDE2`，用于侧栏、筛选条和弱分区。
- 主文字：`#1F1A14`，比纯黑更贴近阅读场景。
- 次级文字：`#70685E`，用于来源、时间、说明。
- 细线：`#DDD2C1`，用于轻边界和分隔。
- 主操作色：`#2F6F5E`，用于播放按钮、主要 CTA、当前导航。
- 收听强调色：`#C98A2E`，只用于进度、当前句和播放状态。
- 失败色：`#B42318`，用于错误和失败状态。

避免大面积渐变、装饰光斑、过多嵌套卡片和低对比米白堆叠。

### 字体和排版

- UI 字体继续使用系统 sans-serif，保证中英文稳定和实现成本低。
- 正文阅读区域使用更舒展的排版：桌面正文宽度约 `64-72ch`，中文行高约 `1.8`。
- 页面标题、列表标题和正文标题通过字号、字重、间距建立层级，不依赖重边框。
- 课程列表和播放器使用紧凑 UI 字号，便于扫读和单手操作。

### 标志性交互

产品记忆点是“随行时间轨”：

- 当前句使用浅琥珀底色、细左线和低对比阴影，表现为收听跟随，而不是调试高亮或批注。
- 播放器进度使用同一琥珀色，形成音频进度和文章位置之间的视觉关联。
- 点击句子仍然跳转到对应音频时间。

## 用户偏好设置

第一轮不做复杂主题系统，先提供真正影响阅读和收听舒适度的偏好：

- 正文字号：小 / 标准 / 大。
- 正文行距：紧凑 / 舒适 / 宽松。
- 左侧栏状态：记住阅读页文章队列的展开或折叠状态。
- 播放倍速：记住上次选择的播放速度。

这些偏好可以先保存在浏览器本地状态中，不依赖认证和账号系统。未来接入认证后，再迁移到用户级设置。

后续可选主题：

- 清亮模式：更白、更适合高亮环境。
- 夜间收听：适合低光环境和睡前收听。

清亮模式和夜间收听不进入第一轮交付。夜间模式需要单独验证正文、图片、Markdown、状态色、播放器和当前句高亮的对比度。

## 信息架构和页面骨架

### 全局壳

桌面端保留左侧全局导航，但降低后台感：

- 品牌区保持简洁，避免过长说明抢占页面。
- 搜索入口保留，视觉上弱于主内容。
- 当前导航使用深绿或深色强调，避免全黑大块压迫。
- 本地开发账号信息保持弱化，不应像生产账号系统。

移动端采用顶部轻导航：

- 顶部展示品牌、当前页面标题或返回入口、菜单按钮。
- 主导航和课程文章队列通过抽屉打开。
- 页面底部空间预留给播放器安全区。

### 工作台

工作台首要回答“现在继续听什么”：

- 顶部保留标题和导入入口。
- 继续学习模块成为第一视觉锚点，展示课程标题、状态、进度、最近位置和继续按钮。
- 指标卡降权为轻量统计，不作为页面主视觉。
- 最近课程使用与课程库一致的列表行，减少卡片堆叠。

### 课程库

课程库使用紧凑列表行，不继续沿用大卡片作为主要列表形态：

- 每行展示标题、字数/句数、进度、状态、更新时间、标签摘要和主操作。
- `ready` 课程主操作为继续/打开；`needs_review` 课程主操作为确认；`failed` 课程突出可重试状态；生成中状态展示等待。
- 删除、星标等低频或次级操作弱化，放到次级按钮或菜单区。
- 筛选区使用轻量分段/选择控件，避免像后台表单。

### 导入页

导入页保持任务导向：

- 粘贴文本和 URL 导入是可用入口。
- 文件上传、浏览器插件等未来能力继续展示为“即将支持”，不做可用态按钮。
- 表单使用安静表面和清晰焦点态，减少容器嵌套。

### URL 确认页

URL 确认页应像阅读一篇清洗后的文章：

- 顶部展示确认任务、来源、字数/句数和主操作。
- 清洗后的内容使用阅读预览样式，而不是信息记录面板。
- “确认并生成音频”只表达进入生成队列，不暗示真实音频已经生成完成。
- 提取中、失败、轮询超时状态提供明确下一步。

## 阅读页设计

### 桌面布局

阅读页由可折叠左侧文章队列和右侧阅读主体组成：

- 左侧展开态宽度约 `18rem`，包含返回课程库、筛选文章、文章队列列表、当前播放位置摘要。
- 左侧折叠态宽度约 `3.5rem`，保留展开按钮和当前队列提示。
- 右侧主体包含课程来源、标题、轻量元信息、正文和主体内播放器。
- 播放器固定在右侧主体底部，不跨过左侧侧栏。

### 移动布局

移动端不显示常驻侧栏：

- 顶部轻导航提供返回、课程文章抽屉入口和当前标题提示。
- 文章队列从抽屉打开，支持筛选和切换。
- 正文占主屏，底部播放器固定并适配安全区域。
- 正文底部预留播放器高度，避免内容被遮挡。
- 正文字号和行距偏好同样适用于移动端，但控件本身放在设置页或阅读页次级入口中，不抢阅读首屏。

### 正文阅读

- 正文不再被明显白色后台卡片包住，而是作为页面主阅读表面。
- 来源信息使用轻量内联元信息展示。
- 标题、元信息、正文、播放器形成清楚层级。
- 当前句高亮使用“随行时间轨”样式。
- 没有音频时间轴时，正文仍可阅读，但句子跳转不伪装为可用播放跳转。

### 自动滚动

- 播放过程中当前句进入视野中部。
- 用户手动滚动后短时间降低自动滚动，避免打断阅读。
- 点击句子跳转时可以立即滚动到对应位置。

## 播放器设计

第一轮使用自定义播放器包裹底层 `<audio>`：

- 播放/暂停。
- 后退 10 秒。
- 前进 10 秒。
- 进度条。
- 当前时间和总时长。
- 倍速控制。
- 当前课程标题或当前句摘要。

状态规则：

- 只有 `ready` 且存在音频 URL 时展示可操作播放控件。
- `needs_review` 展示正文待确认提示和确认入口。
- `text_ready` / `audio_generating` 展示音频尚未可播放的等待说明。
- `failed` 展示失败原因和重试入口。
- 底层 audio 保留但可视觉隐藏，由自定义控件驱动。

## 组件和数据流

优先沿用现有组件边界：

- `ConsoleShell`：统一桌面/移动导航壳、搜索、语言切换和本地账号弱提示。
- `CourseReadingWorkspace`：负责阅读页左右布局、侧栏折叠、移动抽屉、课程切换。
- `CoursePlayer`：负责音频状态、播放进度、保存进度、自定义播放器 UI。
- `MarkdownReader`：负责正文渲染、句子映射、当前句高亮和句子点击。
- `CourseCard` 可演进或拆分为列表行组件，供工作台和课程库复用。
- `PageHeader` 和表单组件统一使用新视觉 token。
- 文案继续集中在 `apps/web/src/lib/i18n.ts`。
- API 访问继续集中在 `apps/web/src/lib/api.ts`。

数据流保持现状：

- 课程列表来自 `listCourses`。
- 课程详情来自 `getCourse`。
- 播放进度继续通过 `savePlaybackProgress` 每隔约 10 秒保存。
- URL 导入继续通过创建、轮询、确认生成的现有流程。

## 错误和空态

- 空课程库：提示先导入内容，并提供导入入口。
- 搜索无结果：提示无匹配课程，保留筛选调整入口。
- 生成中：清楚表达等待，不提供不可用播放控件。
- 待确认：明确下一步是确认清洗正文。
- 失败：展示失败原因和重试按钮。
- API 失败：保留现有错误提示语义，视觉上使用失败色和轻背景。

## 可访问性和响应式

- 所有按钮保留可访问名称。
- 自定义播放器按钮使用真实 `button`，支持键盘焦点。
- 进度条提供可操作控件或明确的 aria label。
- 色彩高亮不作为唯一状态表达，仍保留状态文字。
- 移动端正文和播放器不重叠，使用安全区 padding。
- 折叠侧栏和抽屉状态需要明确按钮文案或 aria 状态。

## 验证计划

实现后运行：

- 前端行为改动：`make test-web`。
- 如果改到路由、Server Component 或 API 连接方式，再运行：`cd apps/web && npm run build`。

人工检查：

- 桌面阅读页：侧栏展开/折叠、播放器不遮挡左侧、句子点击跳转、当前句高亮。
- 移动阅读页：顶部轻导航、文章队列抽屉、底部播放器、安全区和正文遮挡。
- 课程库：列表行扫读、筛选、星标、删除。
- 导入页：文本导入、URL 导入、确认生成、失败/提取中状态。

## 第一轮交付边界

第一轮交付以视觉和交互统一为主：

- 完成主流程视觉 token 和组件样式更新。
- 完成第一轮阅读偏好：字号、行距、侧栏状态、倍速记忆。
- 完成阅读页布局、侧栏折叠、移动抽屉。
- 完成主体内自定义播放器。
- 完成课程库/工作台列表化和命名更新。
- 完成导入页和 URL 确认页风格统一。

不包含：

- 展开播放器。
- 当前文章目录。
- 多主题系统、清亮模式和夜间模式。
- 真实 TTS 接入。
- 认证、支付、文件上传、OCR。
- 大规模后端或数据模型重构。
