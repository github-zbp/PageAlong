# 标签与系列管理设计

Date: 2026-08-20

## Goal

为 PageAlong 增加一套完整的标签与系列管理体验。

本轮要解决的问题是：

- 普通标签要有独立的字典管理页，支持新建、编辑、删除、筛选。
- 系列要保持独立概念，支持新建、编辑、删除、批量删除和阅读入口。
- 课程可以同时属于 0..1 个系列，并绑定多个普通标签。
- 课程详情页是标签绑定的主入口。
- 课程列表页和导入页要补齐对应的轻量交互。

## Current Context

- 当前后端已经有独立的 `course_series` 表。
- 当前课程和系列都还在用 JSON 字符串存标签，这会把“普通标签”和“系列”混在一起。
- 当前 `tags` 页还是占位页。
- 当前课程列表页已经有标签筛选，但列表行只显示字符串标签。
- 当前文本/URL 导入页还在用自由文本 `seriesTitle`。
- 当前系列页已经有列表和详情，但还带着旧的 series 标签语义。
- 真实生产数据里已经有课程、系列、播放进度和导入流程，不应破坏现有内容。

## Confirmed Decisions

- 系列继续是独立实体，不会放进普通标签表。
- 普通标签也会是独立实体，不再挂在 JSON 字符串里。
- 一个课程可以有多个普通标签，但最多只能有一个系列。
- 普通标签的管理只在 `/tags` 页完成。
- 系列的管理只在 `/series` 页完成。
- 课程详情页是标签绑定的主入口。
- 课程列表页只展示标签，不承担标签创建的主流程。
- 导入页的系列输入改成可搜索下拉，并允许直接新建系列再绑定。
- 系列阅读器左侧展示系列内课程列表，并高亮当前课程。
- 普通标签删除时，先从所有课程解绑，再删除标签本身。
- 系列删除前必须先清空课程，或者先删掉课程。

## Scope

### In scope

- 普通标签字典页 `/tags`
- 系列管理页 `/series`
- 课程详情页标签绑定与新建
- 课程列表页标签展示
- 文本/URL 导入页系列选择
- 系列阅读器左侧课程目录
- 新的数据模型和 API 形状
- 迁移现有 JSON 标签数据

### Out of scope

- 普通标签和系列的嵌套层级
- 标签合并工作流
- 标签颜色主题自定义面板
- 系列之间的嵌套文件夹
- 认证、支付、OCR、真实 TTS

## Data Model

### Tags

普通标签需要独立表，而不是继续写入 `tags_json`。

建议字段：

- `id`
- `user_id`
- `name`
- `color`
- `created_at`
- `updated_at`

建议约束：

- 同一用户下名称唯一。
- 名称做 `trim` 归一化。
- 空字符串不允许保存。

### Course tags

课程与普通标签之间使用关联表。

建议字段：

- `course_id`
- `tag_id`
- `created_at`

结果是：

- 一个课程可以绑定多个标签。
- 一个标签可以绑定多个课程。
- 改标签名不会破坏课程绑定。
- 删除标签时只需要先删关联，再删标签。

### Series

系列继续使用 `course_series` 表。

这一轮不把系列改成普通标签，也不要求系列拥有“标签式”管理面板。

建议系列额外保留一个“上次阅读课程”指针，例如 `last_read_course_id`，用于稳定地把“阅读”按钮送回用户上一次打开的课程；如果还没有阅读记录，则可以回退到该系列最新创建或更新的课程，避免空目标。

建议保留的系列字段：

- `id`
- `user_id`
- `title`
- `is_starred`
- `is_deleted`
- `last_read_course_id`
- `last_read_at`
- `created_at`
- `updated_at`

产品面上，系列只作为“课程包标题”和“文件夹”出现。

## Page Design

### `/tags`

页面形态是卡片网格，不是列表。

每个标签卡片展示：

- 名称
- 颜色
- 使用数
- 更新时间

交互：

- 顶部提供搜索框，用于按名称筛选。
- 顶部提供“新建标签”按钮。
- 标签创建时从固定色板里随机分配颜色。
- 点击卡片后，右侧打开详情面板。
- 详情面板内可直接改名、改色、删除。
- 删除前显示这个标签会影响多少课程。

删除语义：

- 删除标签时，先把它从所有课程上移除。
- 然后删除标签记录本身。
- 如果当前筛选正在使用这个标签，界面要自动清空该筛选。

### `/series`

页面形态是列表，不是卡片。

每一行展示：

- 系列标题
- 课程数
- 最近阅读时间
- 阅读按钮
- 编辑按钮
- 删除按钮

交互：

- 顶部提供搜索框。
- 顶部提供“新建系列”按钮。
- 点击标题进入行内编辑，不弹抽屉、不弹框。
- 回车保存，Esc 取消。
- 阅读按钮打开该系列上一次阅读的课程。
- 批量删除通过勾选行来完成。

删除语义：

- 如果系列里还有课程，禁止直接删除。
- 行内或空状态要提示先把课程移走，或者先删除课程。
- 可以保留一个“清空系列课程”的辅助动作，把系列内课程移到普通课程区。
- 批量删除只允许对空系列生效；如果选中的系列里有任意一个非空，就整批阻止并提示先移走课程。

空系列：

- 空系列也要显示。
- 这样导入页先创建系列时，用户在 `/series` 里也能看见它。

### 系列阅读器

系列详情页的左侧展示系列内所有课程，并高亮当前正在看的课程。

交互：

- 左侧支持搜索课程标题。
- 点击课程直接切换到该课程阅读器。
- 移动端同样用抽屉列出课程。
- 当前课程高亮状态和桌面端一致。

阅读入口：

- 系列页的“阅读”按钮优先进入该系列上一次阅读的课程。
- 如果系列还没有阅读记录，则回退到该系列最新课程。
- 如果系列没有任何课程，阅读按钮禁用。

### 课程详情页

课程详情页是标签绑定的主入口。

交互：

- 用带搜索的下拉框选择已有标签。
- 下拉框里提供“新建标签”按钮。
- 用户可以不离开详情页直接新建标签并绑定到当前课程。
- 选择结果用标签 chip 展示，可单独删除。

约束：

- 课程可以绑定多个普通标签。
- 系列不是在这里编辑。
- 详情页只管标签绑定，不管系列编辑。

### 课程列表页

课程列表页的每一行都要展示该课程绑定的标签。

展示规则：

- 默认显示前 2..3 个标签。
- 超出部分折叠成 `+N`。
- 标签 chip 使用对应颜色。

筛选：

- 课程列表页现有的按标签筛选继续保留。
- 筛选来源改成标签字典，不再依赖 JSON 字符串。

### 导入页

文本导入和 URL 导入里的系列输入改成可搜索下拉。

交互：

- 可以选已有系列。
- 输入时可以直接新建系列并绑定到当前课程。
- 如果输入的标题已经存在，优先复用已有系列。
- 新建系列后再提交课程创建。

## API and Behavior

### Tags API

建议新增或调整为：

- `GET /courses/tags`
- `POST /courses/tags`
- `PATCH /courses/tags/{tag_id}`
- `DELETE /courses/tags/{tag_id}`

返回值不再只是字符串数组，而是标签对象列表。

标签对象至少包含：

- `id`
- `name`
- `color`
- `usage_count`

### Series API

建议系列列表和详情继续使用 `course_series` 资源：

- `GET /courses/series`
- `GET /courses/series/{series_id}`
- `POST /courses/series`
- `PATCH /courses/series/{series_id}`
- `DELETE /courses/series/{series_id}`

约定：

- 系列列表要包含空系列。
- 删除非空系列返回冲突错误。
- 列表和详情返回 `last_read_course_id` 与 `last_read_at`。
- 列表里的“阅读”按钮优先使用 `last_read_course_id`，没有阅读记录时回退到最新课程。

### Course payloads

课程创建与更新建议以 ID 为主：

- `series_id`
- `tag_ids`

`seriesTitle`、字符串 `tags` 只作为迁移期兼容输入，不作为新 UI 的主要写法。

## Migration

### Ordinary tags

把当前 JSON 标签迁移到普通标签表和关联表。

迁移顺序建议：

1. 扫描现有课程和系列里的标签文本。
2. 为每个用户创建去重后的标签字典。
3. 写入课程-标签关联表。
4. 课程列表、详情、筛选改为读新表。

### Series legacy tags

当前 `course_series.tags_json` 不能继续作为普通标签来源。

迁移时建议把这些旧值下沉为课程普通标签，然后让新 UI 只读课程标签表。

具体做法是：把某个系列旧标签复制到该系列下所有课程的普通标签关联上，保证课程筛选和课程列表展示不会丢失原来的标签语义。

这样不会丢掉已有标签表现，同时把“系列”和“标签”彻底拆开。

### Compatibility

迁移完成前，旧接口可以短期兼容字符串输入。

但新页面和新组件应该只走新结构：

- 标签用 `id`
- 系列用 `id`
- 标签显示用 `name`
- 颜色显示用 `color`

## Error Handling

- 标签重名时提示已存在。
- 系列重名时直接复用已有系列，而不是创建重复项。
- 删除标签时显示受影响课程数。
- 删除系列时，如果系列非空，显示明确阻止原因。
- 课程详情页如果当前选中的标签已被删除，要自动回退为空选择。

## Testing

建议覆盖这些场景：

- 标签创建后随机颜色可见且可编辑
- 标签删除会解除所有课程绑定
- 课程详情页可搜索、可新建、可绑定多个标签
- 课程列表页能显示前 2..3 个标签并折叠 `+N`
- 系列可新建、可重命名、可删除空系列
- 非空系列删除被阻止
- 系列阅读按钮打开最近阅读的课程
- 系列阅读器左侧高亮当前课程
- 导入页可在输入时新建并绑定系列

## Recommended Component Split

- `TagGridPage`
- `TagInspectorPanel`
- `TagCombobox`
- `SeriesListPage`
- `SeriesRowEditor`
- `SeriesCombobox`
- `CourseTagPicker`
- `SeriesCourseSidebar`

这些组件应当复用同一套标签/系列 API，而不是各页各写一套逻辑。
